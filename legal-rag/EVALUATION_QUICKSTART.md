# Evaluation Harness - Quick Start

## 30-Second Overview

This evaluation system measures how well the retriever finds correct legal document sections for questions. It does NOT modify the pipeline - only measures current performance.

## Two Ways to Run

### Option 1: Via Streamlit UI (Easiest) 🎯

```bash
streamlit run app.py
```

Then:
1. Scroll to "🧪 Model Testing & Evaluation" section
2. Click "Run Evaluation" button
3. Wait for ✅ message
4. Click link to "Evaluation" page in sidebar
5. Explore 5 tabs with visualizations

**Time**: ~10 seconds  
**Output**: Beautiful dashboard with metrics

---

### Option 2: Command Line (For CI/CD)

```bash
python run_evaluation_real.py
```

**Time**: ~10 seconds  
**Output**: Console metrics + `data/evaluation_results.json`

---

## What Happens Automatically

### Step 1️⃣: Build Dataset (First Time Only)
```bash
python build_valid_evaluation_dataset.py
```
✅ Creates 25-30 questions grounded in real corpus chunks  
✅ Tests out-of-corpus questions via retriever  
✅ Saves to `data/evaluation_dataset.json`

### Step 2️⃣: Run Evaluation
```bash
python run_evaluation_real.py
```
✅ Runs all questions through retriever  
✅ Calculates metrics (Recall@1/3/5, MRR)  
✅ Identifies failures with evidence  
✅ Saves results to `data/evaluation_results.json`

## If Something Goes Wrong

### "Evaluation results not found"
→ Run: `python run_evaluation_real.py`

### "Evaluation dataset not found"
→ Run: `python build_valid_evaluation_dataset.py`

### Low metrics (Recall < 60%)
→ Check corpus in vector store  
→ Verify embedding model is loaded  
→ Review similarity threshold in `.env`

### Tests failing
→ Run: `pytest tests/test_evaluator.py -v`

## Common Questions

**Q: Does this modify my pipeline?**  
A: No. Evaluation is read-only. Only measures performance.

**Q: Why do out-of-corpus questions get results?**  
A: By design! Shows what retriever returns for unanswerable questions. Helps identify false positives.

**Q: Can I add more questions?**  
A: Yes. Edit `data/evaluation_dataset.json` with new questions grounded in actual chunks.

**Q: How often should I run this?**  
A: Whenever you change embedding model, vector store, or retriever settings.

**Q: What if Recall@5 is 80%?**  
A: That's okay but could be better. Investigate failed questions to find improvement opportunities.
